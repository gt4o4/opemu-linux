# opemu-linux

Emulation of the instructions a Core 2 (Penryn) CPU lacks — **SSE4.2**
(POPCNT, CRC32, PCMPGTQ, PCMPISTRI/M, PCMPESTRI/M), **AES-NI** and
**PCLMULQDQ** — so prebuilt x86-64-v2 binaries run instead of dying with
`SIGILL`.

Two mechanisms share one arithmetic core:

| dir        | what                                                                 | licence  |
|------------|----------------------------------------------------------------------|----------|
| `core/`    | the arithmetic: PCMPxSTRx on SSE2 (written here — nothing else implements them), the AES rounds and carry-less multiply from BearSSL (MIT), CRC-32C and the AES S-boxes from the kernel's own `lib/` when compiled into it | MIT      |
| `kernel/`  | a Linux **kernel patch**: `CONFIG_X86_UD_EMULATE` executes the faulting instruction from the `#UD` trap, the way UMIP executes `SGDT` & co. from `#GP`; `opemu-match.h` is the header-only matcher for our encodings that the fast path decodes with | GPL-2.0 (the matcher: GPL-2.0 OR MIT, so the tests can include it) |
| `preload/` | an `LD_PRELOAD` library doing the same from a `SIGILL` handler (Zydis-decoded) — the first mechanism, now mainly the test vehicle | MIT |
| `tests/`   | differential tests against real silicon, the VM self-test, a microbenchmark | MIT |
| `dist/`    | `linux-6.18-opemu.patch`, generated by `tools/gen-kernel-patch.sh` — the one artefact a kernel build consumes | GPL-2.0 |

## Why in the kernel

A `SIGILL` handler cannot run in a thread that has the signal blocked: the
kernel resets a blocked *synchronous* signal to `SIG_DFL` and the process dies
with the handler installed and never called.  bun (hence upstream
claude-code) does exactly that during thread start.  A handler also costs a
signal frame plus an `rt_sigreturn` per instruction — about 3 µs on a 3 GHz
Core 2 — where the kernel trap path is a fraction of that.  In the kernel
nothing is delivered to userspace at all.

The trap has two paths and one executor.  The **fast path** keeps
interrupts off, exactly as the trap left them: two `unsafe_get_user()`
qwords under `pagefault_disable()` fetch the instruction, `opemu-match.h`
matches it against the fixed grammar of our encodings (`[66|F2|F3]{0,4}
[REX] 0F (B8|38 xx|3A xx) ModRM [SIB] [disp] [imm8]` — no general decoder,
no GDT read), a register or resident memory operand is read the same way,
and the instruction runs on the task's live registers with no lock (with
interrupts off nothing can touch the FPU; `TIF_NEED_FPU_LOAD`, provably
clear straight from user mode, is checked and sends the trap to the slow
path if set).  The **slow path** is the general one, interrupts on:
`insn_fetch_from_user()`, `insn_decode_from_regs()`, the in-tree
`insn-eval` helpers, `copy_from_user()` (it pages in like any other access;
an unreadable operand becomes the `SIGSEGV` the real instruction's `#PF`
would have been, never a `SIGILL`), `fpregs_lock_and_load()`.  The matcher
only ever says "resolved" or "look again" — refusing (`SIGILL`) and the
operand fault stay with the slow path — so the fast path can emulate exactly
what the slow one would, or hand over: segment and `67` overrides, `LOCK`,
VEX, a page that is not present all go there.  Kernel-mode `#UD`
(`WARN`/`BUG`) is untouched, and the code is inert on a CPU that has the
instructions.

A second decoder is a place to be silently wrong, so the matcher is held to
two oracles: `tests/test-match.c` compares it with Zydis over millions of
encodings at build time, and `opemu_init()` compares it with the kernel's
own `insn_decode_from_regs()` + `insn_get_addr_ref()` over the canned
vectors at boot and refuses to enable the emulator on any disagreement
(`selfcheck_ok 0` in the stats file).

Knobs: `opemu.enable=0` on the command line or
`/sys/module/opemu/parameters/enable` at runtime (the kill switch and the
negative control), `opemu.trace=1` to log refused `#UD` sites, and
`/sys/kernel/debug/opemu/{stats,sites}` for per-family counters, the path
counters (`path_fast`, `path_fallback`, `path_fetch_fallback`,
`path_operand_fallback`), `selfcheck_ok`, and the last sites emulated per
CPU.  32-bit processes are refused (counted as `compat32`).  As with UMIP,
an emulated instruction raises no `#DB` under `TF`.

## Measured

On the machine it was built for (Core 2 Duo E8435 at 3.06 GHz, Linux 6.18.50,
`-march=core2 -O3`), first boot 2026-09-18:

| | |
|---|---|
| POPCNT, per trap | **378 ns** |
| PCMPISTRI, per trap | **855 ns** |
| the same through a userspace `SIGILL` handler | ~3 µs |
| `agy --version` (~104k traps) | **200 ms**, against 300 ms via the preload and 3.70 s under `qemu-x86_64 -cpu Westmere` |
| upstream claude-code `--version` (2,208 traps) | **0.19 s**, full interactive TUI |

Roughly 60% of a POPCNT trap was the hardware exception entry/exit, which no
software can remove; the rest was `insn_decode` plus the core.  The emulator
costs nothing when nothing traps — counters stay flat through ordinary
desktop use, and `ud2` still dies of `SIGILL`.

**Second kernel, same day (generation 307): the fast path and the SSE2 core**,
from a `perf` profile of the first (2 M POPCNT + 2 M PCMPISTRI traps: 237 ns of
hardware entry/exit, 96 ns of the in-tree decoder, 50 ns of glue, 8 ns of
`irqentry`, and 447 ns of the scalar string core):

| | first kernel | second kernel |
|---|---|---|
| POPCNT, per trap | 387 ns | **278 ns** |
| PCMPISTRI (EqualOrdered), per trap | 872 ns | **323 ns** |
| software per POPCNT trap, beside the ~230 ns hardware floor | ~150 ns | **~45 ns** |
| PCMPxSTRx core, direct call (`bench-core`) | 2,245–4,420 cycles | **119–252 cycles** (17–19×; the spread is the P-state) |
| crc32q / pclmulqdq / aesenc / aesdec, direct call | 897 / 419 / 432 / 3,627 cycles | **81 / 162 / 156 / 202** |
| what `perf` sees on the fast path | `insn_decode_from_regs`, `inat_*`, `get_desc`, `rep_movs_alternative`, `_copy_from_user`, `__local_bh_enable_ip`, a `lock xadd` | none of them: `opemu_fixup_ud` 11%, `pcmpstr_core` 6%, `hweight64` 1%; ~75% is the hardware entry/`iretq` (`asm_exc_invalid_op`, `error_entry`, `sync_regs`) |
| path split, 7 minutes of desktop use + 10 M bench traps | — | `path_fast` 15,053,329, `path_fallback` 1 (a `ud2`), `unhandled` 1 |
| boot self-check | — | `77 vectors agree with the kernel's decoder` |
| `agy --version` (~104k traps) | 200 ms | 190 ms (its traps were ~40 ms of that; now ~30) |
| upstream claude-code 2.1.276 `--version` / TUI | 0.19 s / draws | 0.24 s / draws |

What is left per trap is the hardware: `asm_exc_invalid_op` + `iretq` + the
`sync_regs` copy of `pt_regs`, about 230 ns on this Core 2.  Only not
trapping removes that — a first-fault patcher that rewrites hot sites to a
veneer, for which this emulator (first execution, short sites) is the
prerequisite.

### One thing this does not fix, and cannot

A binary that picks code paths by **CPUID** never learns about these
instructions: CPUID is unprivileged and, without CPUID faulting (Ivy Bridge
and later), nothing in the kernel ever sees it.  Two real cases:

- **agy** reads CPUID and calls `go/sigill-fail-fast` before executing
  anything, so it must be patched (a two-gate binary patch; not in this
  repo).
- **bun**, and therefore upstream claude-code, vendors **simdutf**, which
  selects a kernel by CPUID.  Without SSE4.2 it picks the scalar `fallback`
  — and that implementation hangs: it reports "first non-ASCII at index 0"
  for a chunk whose byte 0 is ASCII, so the caller advances by zero forever.
  Forcing `SIMDUTF_FORCE_IMPLEMENTATION=fallback` reproduces the hang on any
  CPU; `SIMDUTF_FORCE_IMPLEMENTATION=westmere` selects the SSE4.2 kernel,
  which this emulator then supplies, and the binary works.  simdutf's own
  documented override does the whole job — no patching, no CPUID spoofing.

The general shape: **this makes the instructions available; something else
still has to make the binary choose to use them.**

## Validation

`core/` is what both mechanisms compute with, and it is checked against the
hardware on a machine that has the instructions:

- `tests/test-emu.c`, `test-vec.c`, `test-gpr.c` — 7,043,843 differential
  checks: every PCMPISTRI/M control byte (all 256 — `imm8[7]` is reserved
  and the silicon ignores it) × 20,000 vectors in four shapes plus fixed
  edge pairs, PCMPESTRI/M over all control bytes, signed lengths and the
  REX.W (64-bit length) form, AES/PCLMULQDQ/PCMPGTQ against the real
  instruction, and the same encoded bytes executed from an RWX page versus
  the decoder-driven path.  The silicon is mandatory: without it the tests
  exit 2, and every test asserts its check count against its loop bounds;
- `tests/test-ref.c` — the SSE2 PCMPxSTRx core against the scalar core it
  replaced (`tests/pcmpstr-ref.c`, kept as an oracle: the silicon certified
  it), 5,125,120 checks, on any x86-64 — the test that runs on the Penryn
  itself;
- `tests/test-match.c` — the kernel's matcher against Zydis: the canned
  vectors, exhaustive ModRM × SIB × REX sweeps and 5M grammar-shaped random
  encodings, 400,767 accepted ones compared field by field down to the
  numeric effective address, plus the truncation contract against a
  `PROT_NONE` page;
- an independent cross-check of the scalar PCMPxSTRx core against GCC's
  testsuite reference model (`gcc.target/i386/sse4_2-pcmpstr.h`, via the
  original opemu): 512,000 cases, zero mismatches — not vendored (GPL vs
  MIT);
- `tests/vm/selftest.c` — boots the real kernel under `qemu -accel tcg -cpu
  Penryn,+xsave` as PID 1 and asserts every family against independent
  known answers (FIPS-197 C.1, the CRC-32C check value, hand-counted bits),
  the mechanism cases (a thread with all signals blocked, a never-touched
  operand page, `PROT_NONE` → `SIGSEGV`, `ud2` and bad encodings → `SIGILL`,
  FS/GS operands, an instruction window and an operand reaching into an
  unmapped page with the `SIGSEGV` address still exact, all sixteen XMM
  registers intact around the string forms), a negative control with
  `enable=0`, and counters — per family AND per path — equal to the exact
  executed counts; a second boot on Westmere proves inertness;
- `tests/bench/bench.c` — ns per emulated POPCNT and PCMPISTRI on the
  target; `tests/bench/bench-core.c` — cycles per direct call of the core,
  no traps, beside the scalar reference.

## Building the kernel patch

```
tools/gen-kernel-patch.sh          # -> dist/linux-6.18-opemu.patch
patch -p1 < dist/linux-6.18-opemu.patch   # in a 6.18 tree; then CONFIG_X86_UD_EMULATE=y
```

The patch adds `arch/x86/kernel/opemu.c`, `opemu-match.h` +
`opemu-match-vectors.h`, `opemu-core.{c,h}` (a copy of `core/`),
`arch/x86/include/asm/opemu.h`, one Kconfig option (which selects `CRC32`
and `CRYPTO_LIB_AES` for the tables the core borrows), one Makefile line and
the call in `exc_invalid_op()`.  Written against 6.18.50; the hunks are
small and the context is ordinary.

## Lineage

Forked from [mirh/opemu-linux](https://github.com/mirh/opemu-linux), itself a
port of the XNU "Opcode Emulator" (Sinetek, AnV, Bronzovka, Meowthra) to a
Linux kernel module.  That code could not build on a current kernel
(`kallsyms_lookup_name` unexported since 5.7, `FTRACE_OPS_FL_RECURSION_SAFE`
gone in 5.11, `asm/fpu/internal.h` gone in 5.16) and its operand/flag wiring
was wrong; its PCMPxSTRx core was GCC's reference model and served as the
cross-check above.  The name, licence and history are kept; the code is
replaced.  Built for and measured on iMacGBC, a 2009 iMac with a Core 2 Duo
E8435, from [gt4o4/nix-configs](https://gitlab.com/gt404/nix-configs).
